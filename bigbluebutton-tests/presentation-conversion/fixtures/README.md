# Fixtures

Every fixture is one manifest file, `fixtures/<tier>/<id>.yaml`, usually next to the file it uploads.

| Tier | Directory | Bytes committed? |
|---|---|---|
| synthetic | `synthetic/` | yes, produced by `generators/` (deterministic) |
| repo | `repo/` | no, the manifest points at a file already in the repository |
| variant | `variants/` | no, re-uploads another fixture's file under different conditions (name, method, create params) |
| runtime | `runtime/` | no, generated by the harness at run time (`src/runtimeFixtures.ts`) |
| public | `public/` | yes, with a `NOTICE` entry (reproducers attached to public GitHub issues) |
| private | `private/` | no, phase 2; not wired yet (see `private/README.md`) |

## Manifest

```yaml
id: pdf-base14-text-3p                # unique; lowercase, digits and hyphens; equals the file stem for synthetic files
title: Three pages of base-14 text, page 3 holds only "12"
tier: synthetic
file: pdf-base14-text-3p.pdf          # relative to this manifest; repo/variant tiers may point elsewhere in the repository
# generate: { kind: padded-pdf, bytes: 500000, seed: 1 }   # runtime tier only, instead of `file`
issues: [15209, 24231]                # issues and PRs this fixture guards
catalog: ["Numeric-only slide text", "Timeout unit mismatch"]   # category names from the kinks catalog
upload:
  method: create                      # create | insertDocument | create-url | insertDocument-url
  name: pdf-base14-text-3p.pdf        # optional, defaults to "<id>.<extension of file>"
pages: 3                              # pages expected when converted
expect: converted                     # converted | rejected:<ERROR_KEY> | dropped | measure
expectByProfile:                      # optional, per-profile override of `expect`
  tight-limits: converted
kind: vector                          # vector | raster | blank | any, or a map { <profile>: <kind> }
pageOverrides:                        # optional, per page; same keys as the page-level fields below
  3: { kind: vector }
marker: false                         # true: every page shows the marker picture (red top, blue bottom,
                                      # green left, yellow right); { split: 2 } for two side by side
aspect: auto                          # auto (compare with the PDF page box) | <number> | none
checks: [outcome, pages, kind, aspect, exif, text, marker, pixels, thumb]   # optional subset; default: all that apply
tolerance: { maxDiffPixelRatio: 0.01 }   # optional
profiles: [defaults]                  # profiles that upload this fixture; default [defaults]
goldenProfiles: [defaults]            # profiles with their own goldens; the others compare with the defaults goldens
createParams: {}                      # optional extra create parameters; the fixture then gets its own meeting
notes: free text
```

Rules the manifest lint enforces:

- `id` is unique and matches the manifest file name.
- `file` exists, unless the tier is `runtime` or `private`.
- Base64 uploads (`create`, `insertDocument`) must stay under 650 000 bytes per file. nginx caps the request body of `/bigbluebutton/api/*` at its 1 MB default, so bigger files use `create-url` or `insertDocument-url`.
- `rejected:<ERROR_KEY>` uses the key akka-apps stores in `pres_presentation.uploadErrorMsgKey`: `FILE_TOO_LARGE`, `PAGE_COUNT_EXCEEDED`, `PAGE_COUNT_FAILED`, `CONVERSION_TIMEOUT`, `OFFICE_DOC_CONVERSION_FAILED`, `OFFICE_DOC_CONVERSION_INVALID`, `INVALID_MIME_TYPE`, `FILE_VIRUS`, `SCAN_FAILED`.
- `dropped` means the upload left no presentation behind: no directory and no database row. That is how `create` reports most rejections today.
- `measure` records whatever happens and never fails. Use it for a new fixture until its first run shows the behaviour, then freeze the observed outcome.

## Checks

| Check | What it asserts |
|---|---|
| outcome | the result matches `expect`: converted, the expected error key, or dropped |
| pages | converted page count equals `pages` |
| kind | each slide SVG is `vector` (pdftocairo output), `raster` (one embedded PNG, no `<path`), or `blank` (the 317-byte blank slide) |
| aspect | slide aspect ratio within 1 % of the PDF page box, or of the manifest value |
| exif | no JPEG embedded in a slide SVG carries an EXIF Orientation other than 1 (#26001) |
| text | `textfiles/slide-N.txt` equals its golden |
| marker | the rendered slide shows the marker picture upright and unmirrored |
| pixels | the rendered slide matches its golden PNG within the tolerance |
| thumb | the thumbnail matches its golden PNG within the tolerance |
| served | slide 1 is served to a joined session (cookie, sessionToken, pageToken) with the same bytes as on disk, and refused with a wrong pageToken; runs for every converted fixture that enables it |

Known failures are listed in `../known-failures.yaml`, per fixture, profile, page and check.

## Synthetic generators

`generators/` holds the Python that writes `synthetic/`. It runs in a pinned container, so neither the laptop nor the server needs Python packages:

```bash
fixtures/generators/run.sh            # regenerate every synthetic fixture and manifest
fixtures/generators/run.sh --check    # regenerate into a temporary directory and compare sha256
```

Generated files must be byte-for-byte reproducible: fixed dates and document IDs, fixed random seeds, normalised zip entries for Office files.
